# 1. epoll有没有mmap？

**答案：epoll底层使用了mmap，但不是给用户手动调用mmap。**

### 详细解释

epoll在`epoll_create`的时候，内核会**mmap一块共享内存**，这块内存是用户态和内核态共享的就绪事件缓冲区。 目的：`epoll_wait`获取就绪事件时，**不需要把事件从内核拷贝到用户态**，直接读这块共享内存，减少一次内存拷贝开销。

> 注意面试坑：

1. **用户代码不需要自己写mmap**，这个mmap是epoll内核内部自动完成的，对上层透明。
2. select/poll**没有mmap**，每次都要在内核态、用户态之间拷贝数据。
3. 很多人会混淆：mmap是epoll的优化手段，**不是epoll的核心原理**，epoll核心是红黑树+就绪链表，mmap只是用来优化事件拷贝。

> 一句话背诵版：epoll内核内部使用mmap建立用户/内核共享内存，减少epoll_wait时的事件拷贝；上层用户程序感知不到，不用手动调用mmap。

# 2. epoll是否线程安全？

**答案：epoll的fd（epoll实例）本身是线程安全的。**

### 详细解释

epoll的文件描述符是内核对象，内核内部对epoll实例做了锁保护：

- 多个线程**同时调用 epoll_ctl（add/mod/del）**、**多个线程同时epoll_wait**，内核层面不会出现数据损坏、崩溃。
- 但是！**事件处理逻辑不是线程安全**。
    
    > 举例子： 两个线程epoll_wait拿到同一个就绪fd，两个线程同时去recv这个socket，就会出现并发读的竞态问题，**这个竞争是socket层面的，不是epoll本身的bug**。
    

#### 面试重点区分

1. ✅ **epoll对象本身操作（epoll_ctl、epoll_wait）内核是线程安全，内核自带锁**，多线程并发调用这几个系统调用不会破坏epoll内部红黑树。
2. ❌ **业务层面不是天然安全**：多个线程拿到同一个就绪fd，并发读写socket，会产生数据竞争，需要自己加锁或者用多Reactor的方案规避。

> 背诵版：epoll实例本身线程安全，内核有锁保护epoll_ctl/epoll_wait；但epoll只负责分发事件，**拿到事件后的socket读写业务逻辑，需要自己保证并发安全**。

---

## 面试精简口述

1. epoll内核内部使用mmap创建一块用户内核共享内存，优化就绪事件拷贝，用户代码不需要手动调用mmap。
2. epoll本身是线程安全的，内核内部加锁保护epoll对象，多线程并发epoll_ctl、epoll_wait不会损坏epoll结构；但是epoll分发出来的socket事件，多线程处理时会有竞态，业务代码要自己处理并发安全。
