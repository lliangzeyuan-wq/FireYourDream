# epoll    LT（水平触发） vs ET（边沿触发）

> LT = Level Trigger，水平触发；ET = Edge Trigger，边沿触发 epoll**默认是LT**，ET需要手动加 `EPOLLET` 标志。

## 1. LT 水平触发（默认）

一句话：**只要缓冲区还有数据没读完，每次epoll_wait都会反复通知这个fd就绪**。

举例子：客户端一次性发 1000 字节，你的buffer只读了 200 字节，内核缓冲区还剩800字节。

1. epoll_wait 返回，通知fd可读
2. recv读200字节，**缓冲区还有剩余数据**
3. 下一轮 `epoll_wait` **还会再次触发这个fd的EPOLLIN事件**，继续通知你去读剩下的数据。

特点：

- 简单、不容易写崩，select/poll本质都是LT模式
- 缺点：如果数据没读完，会反复唤醒epoll，有更多系统调用开销
- 代码写法：**不用一次性读完缓冲区，读一部分没关系**

## 2. ET 边沿触发 Edge Trigger

一句话：**只有状态发生变化的一瞬间才通知一次**。

> 只有从【无数据】→【有新数据到达】这个边沿时刻，触发一次事件。

同样例子：客户端发1000字节，buffer只读200，缓冲区剩800：

1. 新数据到达，触发一次EPOLLIN，epoll_wait返回
2. recv读200字节，缓冲区还有800
3. **不会再触发事件！** 除非再有新数据进来，才会再次通知。

⚠️ ET强制要求：

> **一旦收到事件，必须循环recv，一次性把内核缓冲区全部读完，读到recv返回-1，errno==EAGAIN为止**。 否则剩下的数据永远不会再触发事件，数据留在缓冲区卡死。

ET一般搭配**非阻塞IO（O_NONBLOCK）**使用。如果用阻塞fd + ET，很容易死锁。

## 对比表

|项目|LT 水平触发|ET 边沿触发|
|---|---|---|
|触发时机|缓冲区有数据，就持续通知|仅数据到来的瞬间通知一次|
|读数据要求|可以分次读，不用一次性读完|**必须循环读完缓冲区全部数据**|
|默认|epoll默认LT|需要手动加EPOLLET|
|复杂度|简单，容错高|复杂，容易丢数据|
|性能|多次epoll唤醒，开销更大|唤醒次数少，高性能，高并发常用|

## 大白话类比

- LT：水位只要高于警戒线，就一直喊你（有水就通知）
- ET：水位刚涨上来那一瞬间喊你一次，之后哪怕还有水，也不喊了，等下一次水位上涨

## 和你刚才epoll代码关联

你前面写的epoll代码，**没有设置EPOLLET，是LT模式**。 就算一次recv只读128字节，缓冲区剩下的数据，下一轮epoll_wait还会再次触发事件继续读。

如果改成ET模式，代码必须改成：

1. clientfd设置为非阻塞
2. 收到事件后while循环recv，直到返回-1 && errno == EAGAIN

```
// ET模式读取示例
while(1)
{
    char buffer[128]={0};
    int count = recv(connfd, buffer, 128, 0);
    if(count > 0)
    {
        send(connfd, buffer, count,0);
    }
    else if(count == 0)
    {
        // 断开
        break;
    }
    else if(errno == EAGAIN)
    {
        // 缓冲区读完了，退出循环，等待下一次事件
        break;
    }
}
```
